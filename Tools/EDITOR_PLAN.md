# План: веб-редактор базы ремапа (remap_table.json)

> Контекст для старта в новой сессии. Задача — сделать **второй веб-интерфейс**
> для удобного редактирования самой базы данных ремапа префабов.

## Решения (утверждены пользователем)

1. **Размещение:** та же страница-сервер, новый маршрут `/editor`, тот же
   `Serve-RestoreUI.ps1` на `:8787`. Минимум дублирования, единый бэкенд.
2. **Представление:** **оба режима** с переключателем — плоская таблица и дерево.
3. **Запись файла:** **свой детерминированный сериализатор в ядре** (не
   `ConvertTo-Json`, который экранирует `>` в `\u003e` и может переупорядочить).
4. **Объём правок:** полный набор — добавить / удалить / переместить / подобрать /
   править `_meta`.

## Что уже выяснено про базу

- `Tools/remap_table.json`: **154 листа** (136 заполнено, 18 заглушек).
  Ключ = `{GUID}СтарыйПуть.et`, значение = `{GUID}НовыйПуть.et` или `""` (заглушка).
- Форма разношёрстная (лист = любое свойство, чьё имя похоже на реф, на любой глубине):
  - `Characters` — вложен на 4 уровня (Категория › Фракция › Тип)
  - `Props` — 3 уровня
  - `Groups` — 2 уровня
  - `RestoreFix_MissingDRG` — плоская (28 прямых листьев)
  - `_Unresolved_Pending` — плоская (27 прямых листьев)
- Текущий `Set-RemapEntries` для редактора **не годится**: умеет только добавить
  (в плоский `_Unresolved_Pending`) и поменять значение; нет удаления/переноса/
  переименования/правки `_meta`; запись через `ConvertTo-Json -Depth 50` портит
  структуру (экранирует `>`, может переупорядочить).
- `Build-ModIndex` даёт карту `GUID→путь` по всему моду (~4735 записей) — основа
  валидации: по новому рефу проверяем, что GUID существует И путь ему соответствует.
- Переиспользуем весь бэкенд: один `Serve-RestoreUI.ps1`, одно ядро
  `Restore-Core.ps1`, тёмная тема с CSS-переменными из `UI/index.html`.

## Файлы в работе

- `Tools/Restore-Core.ps1` — ядро (функции ранкера/ремапа/ИИ)
- `Tools/UI/Serve-RestoreUI.ps1` — HttpListener-бэкенд, маршруты `/api/*`
- `Tools/UI/index.html` — существующий UI восстановления миссий (образец темы/стиля)
- `Tools/UI/ui.config.json` — пути, порт, ИИ-настройки
- `Tools/UI/editor.html` — **НОВЫЙ** файл редактора базы

## План реализации

### 1. `Tools/Restore-Core.ps1` — новые функции

- **`Format-RemapJson`** — детерминированный сериализатор: обход упорядоченного
  графа, отступ 4 пробела, UTF-8 без BOM, экранируются только обязательные
  JSON-символы (Кириллица/`>`/`<` остаются литералами), порядок ключей и
  вложенность сохраняются. Ядро безопасной записи.
- **`Validate-RemapEntry`** — по старому/новому рефу + индексу мода возвращает
  статус: `ok` / `stub` / `target-missing` / `path-mismatch` / `malformed` / `dup`.
- **`Get-RemapModel`** — парсит файл в структуру для API: `_meta`, дерево групп,
  плоский список листьев (с хлебными крошками группы + статусом валидации).
- **CRUD по графу с сохранением вложенности** (все через `Backup-RemapTable` +
  `Format-RemapJson`): `Set-RemapLeafValue`, `Add-RemapLeaf`, `Remove-RemapLeaf`,
  `Move-RemapLeaf` (смена группы), `Rename-RemapKey`, `Set-RemapMeta`.

### 2. `Tools/UI/Serve-RestoreUI.ps1` — новые маршруты

- `GET /editor` → отдаёт `editor.html`
- `GET /api/table` → `_meta` + дерево + плоский список + валидация
- `GET /api/modindex` → карта `GUID→путь` (однократно на клиент для мгновенной
  валидации без круговых запросов)
- `POST /api/table/save` → принимает **список операций**
  (set/add/delete/move/rename/meta); один бэкап + одна запись через сериализатор;
  возвращает обновлённую валидацию
- Подбор замен для заглушек **переиспользует** существующие `/api/suggest` и
  `/api/ai-suggest` — новых эндпоинтов не нужно.

### 3. `Tools/UI/editor.html` — новая страница (та же тёмная тема)

- Переключатель **Таблица / Дерево** в шапке + поиск + чипы-фильтры
  (все / заполнено / заглушки / битая цель / дубликаты) + счётчики.
- **Плоский режим:** строки «крошки группы › старый реф → новый реф (редактируемый,
  с индикатором валидности)»; действия в строке: *подобрать* (для заглушек —
  кандидаты из suggest/ИИ), *удалить*, *переместить*.
- **Режим дерева:** сворачиваемые узлы Категория › Фракция › Тип, тот же редактор листа.
- Панель правки **`_meta`** (description / status).
- Форма добавления записи (группа + старый реф + новый реф).
- **Сохранение — пакетное:** правки копятся на клиенте, кнопка
  «Сохранить изменения (N)» шлёт их одной операцией → один `.bak` + одна запись
  (меньше мусорных бэкапов, атомарный дифф).
- Валидация **мгновенная** на клиенте по `/api/modindex`.
- Перекрёстные ссылки: кнопка `→ Редактор базы` в `index.html` и
  `→ Восстановление` в редакторе.

### 4. Проверка (этап выполнения)

- Round-trip: загрузить → сериализовать без правок → reparse совпадает
  (порядок, Кириллица, нет `\u003e`); счётчики 136/18 сохраняются.
- Каждая CRUD-операция → reparse → `Load-RemapTable` и `Restore-Mission`
  по-прежнему читают файл.
- `node --check` на извлечённом JS редактора (как делали для `index.html`).
- Перезапуск сервера, смоук всех эндпоинтов.

## На что обратить внимание

- Первое сохранение из редактора **переформатирует весь файл** под новый
  сериализатор (отступы отличаются от текущего `ConvertTo-Json`-стиля) — будет
  один крупный разовый дифф. Дальше диффы чистые и минимальные.
  Вариант: один раз прогнать нормализацию отдельным коммитом, чтобы «большой дифф»
  и смысловые правки не смешивались.
- `remap_table.json` сейчас читается через `Read-Text` (авто-BOM); писать нужно
  UTF-8 **без BOM** (как `Write-Text` в ядре) — проверить фактический BOM файла
  перед первой записью.
- Лист может лежать на любой глубине и в плоских секциях — редактор обрабатывает
  плоскую и вложенную форму единообразно.
